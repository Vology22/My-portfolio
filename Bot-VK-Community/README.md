# VKzakaz — VK-бот сообщества

Один бот, три функции:
1. **Объявления** — приём объявлений от пользователей через диалог с ботом, модерация, автопубликация на стену по расписанию, отслеживание подписки автора и периодическое подтверждение продления.
2. **Анализ конкурентов** — поиск крупнейших пабликов по теме и городу.
3. **Агрегатор** — автоматический репост постов из заданных сообществ-конкурентов в своё сообщество, без изменений, с категорией по источнику.

Интерфейс полностью кнопочный — ни пользователю, ни администратору не нужно вводить текстовые команды. Бот реагирует на любое сообщение: если для отправителя нет активного диалога (визарда подачи объявления или админского сценария), бот показывает главное меню с кнопками.

> Бот №3 публикует чужой контент без изменений и без указания источника. Это осознанное решение владельца проекта — учитывайте риск блокировки автоматизации со стороны VK и вопросы авторских прав на публикуемые материалы.

## 1. Настройка сообщества VK

1. Создайте сообщество VK (тип «Публичная страница» или «Группа») — vk.com → Сообщества → Создать сообщество.
2. Зайдите в **Управление → Работа с API → Ключи доступа** и создайте ключ доступа сообщества (Group Token). Отметьте права: `wall` (публикация на стену), `photos`, `docs` (доступ к вложениям), `messages` (переписка с пользователями), `manage` (базовое администрирование через API).
3. Там же, в **Работа с API → Callback API → Типы событий**, включите: «Входящее сообщение», «Вступление в сообщество», «Выход из сообщества», «Добавление комментария на стене», «Отметки «Мне нравится»». Это нужно сделать, даже если Callback URL не настраивается — бот получает эти же события через Long Poll, но типы событий должны быть включены в настройках сообщества. Последние два пункта нужны для уведомлений админам о комментариях и лайках (🛠 Админ-панель → 🔔 Мои уведомления) — без них эти два типа уведомлений просто не будут приходить, при этом остальной бот продолжит работать нормально.
4. В **Работа с API → Long Poll API** включите Long Poll, версия API — актуальная (тип отправки данных не важен, бот использует Bots Long Poll напрямую).
5. **Управление → Сообщения** — убедитесь, что сама функция сообщений сообщества включена (отдельный переключатель, не относится к API).
6. **Управление → Сообщения → «Возможности ботов»** (внизу страницы) — включите пункт, разрешающий сообществу вести себя как бот. Без этого шага VK будет возвращать ошибку `VKAPIError_912: This is a chat bot feature` при любой попытке бота отправить сообщение с клавиатурой (а у бота клавиатура почти в каждом ответе).
7. Узнайте числовой ID сообщества (Управление → Обзор, либо из URL `vk.com/club<ID>` или `vk.com/public<ID>`) — либо просто передайте токен боту: при первом запуске он сам определяет ID через `groups.getById`.

## 2. Установка и запуск локально

```bash
python -m venv venv
venv\Scripts\activate        # Windows
pip install -r requirements.txt
copy .env.example .env       # затем заполнить GROUP_TOKEN, GROUP_ID, ADMIN_IDS
python -m bot.main
```

`ADMIN_IDS` — VK ID администраторов/редакторов через запятую (свой ID можно узнать на vk.com/id или в настройках профиля).

При первом запуске бот сам создаёт файл SQLite (`DB_PATH`) и заполняет настройки по умолчанию.

## 3. Первая проверка (сценарий бота №1)

1. Напишите боту любую фразу от аккаунта, добавленного НЕ в `ADMIN_IDS` — появится главное меню. Нажмите «📢 Подать объявление» и пройдите визард: категория → платное/бесплатное → текст → фото (или «Без фото») → «Отправить на модерацию».
2. От аккаунта из `ADMIN_IDS` придёт карточка объявления с кнопками «Одобрить»/«Отклонить» — нажмите «Одобрить».
3. В течение часа (интервал `auto_publish` в `bot/scheduler.py`) объявление будет опубликовано на стену сообщества.
4. Чтобы не ждать реальный месяц/дни при проверке продления и заморозки — зайдите в 🛠 Админ-панель → ⚙️ Настройки и уменьшите интервалы (можно выбрать «Своё значение» и ввести `0`).

## 4. Интерфейс

**Пользователь** (главное меню приходит на любое сообщение):
- 📢 Подать объявление — визард (категория → платное/бесплатное → текст → фото → подтверждение)
- 📋 Мои объявления — статус поданных объявлений
- При заморозке объявления бот сам пришлёт кнопки «Продолжить» / «Редактировать» / «Удалить»

**Админ** (кнопка 🛠 Админ-панель видна только VK ID из `ADMIN_IDS`):
- 🗂 Модерация — очередь объявлений с кнопками «Одобрить»/«Отклонить»
- ⚙️ Настройки — интервал продления, срок ответа до удаления, частота публикации своих постов (теперь в минутах, от 5 минут), лимит и глубина по давности постов конкурентов для агрегатора, срок повторной публикации поста конкурента при нехватке новых (пресеты или «Своё значение»), а также подменю «Тексты уведомлений» для редактирования шаблонов сообщений
- 🏷 Категории — список категорий + «Добавить категорию» (порядок добавления категорий = порядок ротации агрегатора по тематикам, см. ниже)
- 📊 Анализ конкурентов — бот спросит тему и город по очереди, затем пришлёт отчёт
- 🔁 Источники (агрегатор) — список источников, добавление (ссылка/ID сообщества → выбор категории кнопкой) и удаление; экран также показывает, какая категория сейчас «в ротации» (за один цикл опроса берутся источники только одной категории, дальше по кругу)
- 🔔 Мои уведомления — персональные вкл/выкл переключатели: новые подписки/отписки, комментарии на стене, лайки на постах, сообщения от пользователей без активного диалога. Настройка у каждого администратора своя (см. п.1 про типы событий Callback API для комментариев/лайков)
- 🎯 Аудитория конкурентов — список кандидатов (участники тех же сообществ-конкурентов, что заданы в «Источники»), прошедших фильтр по мин. числу друзей/подписчиков, городу и ключевым словам в тематических подписках, плюс редактирование самих критериев. Бот только подбирает и показывает кандидатов — писать им или добавлять в друзья нужно вручную, массовых автоматических действий бот не выполняет (см. CLAUDE.md и ТЗ_новые_функции.txt)

## 5. Деплой на VPS

1. Скопируйте проект на сервер, установите зависимости так же, как в п.2 (Linux: `python3 -m venv venv && source venv/bin/activate`).
2. Заполните `.env` на сервере реальными значениями.
3. Systemd-юнит `/etc/systemd/system/vkzakaz.service`:

```ini
[Unit]
Description=VKzakaz bot
After=network.target

[Service]
WorkingDirectory=/opt/vkzakaz
ExecStart=/opt/vkzakaz/venv/bin/python -m bot.main
Restart=always
RestartSec=5
EnvironmentFile=/opt/vkzakaz/.env

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now vkzakaz
sudo journalctl -u vkzakaz -f    # логи
```

Публичный HTTPS/домен не требуется — бот сам подключается к VK через Long Poll.

## Структура проекта

```
bot/
  main.py                   # точка входа: сборка Bot, регистрация labeler'ов, запуск планировщика
  config.py                 # чтение .env
  vk_client.py              # единый API-клиент сообщества (используется вне контекста сообщений — в job'ах и raw-событиях)
  vk_utils.py                # random_id для messages.send/wall.post
  vk_attachments.py           # общий разбор вложений (фото/видео/документы) в строку для attachments
  admin_draft.py               # KV-хелперы для AdminDraft (многошаговые админские сценарии без команд)
  scheduler.py               # регистрация всех периодических job'ов
  db/
    models.py                # SQLAlchemy-модели
    session.py                # async engine/session, init_db()
    settings_repo.py           # KV-настройки, редактируемые из «⚙️ Настройки»
  modules/
    posts/                   # Бот №1 — объявления
      client.py               # главное меню, визард подачи, «Мои объявления», ответы на заморозку
      admin.py                 # модерация, все экраны админ-панели (настройки/категории)
      dispatcher.py             # ЕДИНСТВЕННЫЙ message-обработчик: кнопки + продолжение диалогов
      events.py                  # group_join/group_leave/wall_reply_new/like_add (события + уведомления админам)
      jobs.py                    # check_subscriptions, renewal_reminder, freeze_expiry, auto_publish
      notifications.py            # NotificationPreference: кто из ADMIN_IDS на что подписан + рассылка
      keyboards.py                # все клавиатуры бота (в т.ч. общих экранов admin-панели)
      attachments.py               # вложения сообщений -> attachments
      subscriptions.py              # groups.isMember, регистрация пользователя
    competitors/              # Бот №2 — анализ конкурентов
      admin.py                 # диалог «тема → город → отчёт»
      vk_search.py               # groups.search, database.getCities, проверка активности
    aggregator/                # Бот №3 — агрегатор
      admin.py                 # экраны источников (добавить/список/удалить)
      poller.py                  # ротация категорий, лимит/давность/TTL-повтор, репост новых постов источников
    audience/                  # Кандидаты из аудитории конкурентов (список для ручной обработки, без автоматизации)
      admin.py                 # экраны критериев фильтра и списка кандидатов
      poller.py                  # снапшот участников источников + фильтрация новых по критериям
```

## Известные ограничения MVP

- Модерация и админ-панель работают в личных сообщениях с ботом (не в беседе).
- Список редактируемых текстов уведомлений фиксирован (см. `TEXT_KEY_LABELS` в `bot/modules/posts/keyboards.py` и `DEFAULT_SETTINGS` в `bot/db/settings_repo.py`).
- Бот №3 не проверяет права на контент конкурентов — это сознательно принятый риск (см. предупреждение в начале файла).
- В `bot/main.py` временно включено подробное debug-логирование (`logging.basicConfig(level=logging.DEBUG)`) для диагностики при первом запуске — перед боевой эксплуатацией стоит понизить уровень до `INFO` или убрать вовсе.
